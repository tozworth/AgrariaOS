# Options window

The Pelicom Options button uses the vanilla options-tab sprite (`mouseCursors`, 96, 368, 16 × 16). It opens a draggable, resizable desktop window with the usual minimize, restore, close, grouping and per-farmer persistence.

The left pane uses the shared `TreeView`, starting with **System** for Agraria settings, followed by the categories and localized names from the installed game's `OptionsPage` headers. System contains the Pelicom auto-hide checkbox (saved in config) and position dropdown (Left / Right / Top / Bottom, saved per farmer). Auto-hide slides the rail offscreen after one second away, with a 160 ms eased animation. Hover the outermost two pixels of its screen edge to reveal it; rail presses, icon dragging and desktop context menus keep it open. Presses begun outside the rail do not reveal it while dragging or resizing at an edge. Disabling auto-hide restores the full rail immediately. These controls replace their Pelicom right-click entries; Reset icon order remains there. The right pane shows only the selected category's options, with wheel and thumb scrolling. Vanilla supplies which game settings are available to this player, including host and split-screen restrictions. Returning from a native menu or changing multiplayer context refreshes the available categories.

Desktop windows use the full viewport, including the absolute bottom edge, regardless of auto-hide. Pelicom draws above their frames and receives clicks and wheel input before the windows it covers; desktop context menus remain above it. Hidden portions have no click targets. Animation state is per screen and moving the rail resets it to fully visible. The pinned rail still offsets the status readout and bottom toolbar; auto-hide removes those HUD insets without moving them during each slide.

System also has an **Experimental** heading with an **Extended queue** checkbox, saved as `ExtendedQueue` in config and off by default. Enabling it removes the nine-target limit for click/drag queues and Overview Ctrl/Shift selection and bulk actions immediately. Disabling it limits new additions without dropping existing queued work or hiding its indicators. Queue brackets and animal outlines use gradual rainbow hues, starting at cyan and completing a smooth cycle every 30 entries; adding targets keeps existing colors stable. Overview batches of up to nine retain exact route optimization; larger batches visit the nearest reachable target and interaction side at each stop using bounded searches.

The same Experimental section has a **Right-click drag** dropdown: **Per-tile** (default) and **Box select**, saved as `RightClickDrag`. Per-tile keeps the existing collection stroke. Box select can begin on empty ground and shows a translucent white rectangle with a black/white checkered border. Release queues valid targets on all covered tiles as one batch, preferring output-only collection/petting and then other supported right-click interactions, including harvestable bushes and text signs. Target filtering is deferred. Existing routes pause while the box is held; shrinking changes the final selection. A click without dragging dispatches one target on release. The normal queue limit still applies: enable Extended queue for boxes with more than nine targets. With it off, oversized batches are rejected together. Shift, manual movement, another button, menus, UI entry, F8, lost focus, map/day changes and returning to title cancel selection. Shift-right-click stays vanilla, and furniture placement keeps its existing input.

The category pane and action buttons use measured widths from the active font and localized labels. Slider percentages have a stable column sized for every value from 0% through 100%, with space reserved for the slider track. The window's minimum width includes both panes so resizing does not cut off category names, screenshot actions or percentage suffixes while the viewport can accommodate that minimum.

Checkboxes, dropdowns, sliders, zoom/UI-scale steppers, key bindings and action buttons use Agraria styling. Changes call vanilla setting APIs and save default options; sliders save when the drag ends. Key rebinding preserves vanilla duplicate-key validation and Escape cancellation. F8 remains the HUD fallback. Screenshot and multiplayer actions keep their native behavior and dialogs.

## Shared controls

`UI/FormControls.cs` draws fields, buttons, checkboxes, dropdown anchors and sliders. Dropdown indicators use pixel geometry so font size and text fitting cannot hide the arrow. Owners supply values, enablement, hit testing and persistence. `TextEntry` uses the same field styling for editable inputs. `UI/DropdownList.cs` owns a bounded popup with wheel scrolling, arrow/Home/End navigation, Enter selection and Escape/outside-click dismissal. Draw a dropdown after the owning pane's other contents; its layout and hit bounds stay within that pane. These controls use the existing SpriteBatch and pixel-aligned text.

Options tracks keyboard capture intent separately from its dispatcher's `Selected` flag. Vanilla clears that flag during `UpdateOther` outside menus; the desktop restores the subscriber while Options still wants focus. A deliberate desktop blur releases that intent, with dismissal deferred until content clicks can select or cancel the open popup.

## Verification

The release build uses Stardew Valley 1.6.15 and SMAPI 4.5.2. Isolated checks against the compiled mod cover dropdown bounds, long lists, wheel limits, keyboard selection/cancellation, click selection/dismissal, Options capture across vanilla subscriber resets and deliberate blur, and slider endpoints. Text sizing checks use the installed SmallFont assets at 1×, 1.5× and 2× to verify category labels, screenshot buttons, all percentages and the combined minimum width. They do not verify graphics or loaded-save behavior.

After a normal launch:

1. Open Options from Pelicom. Confirm System is first; enable auto-hide and check the one-second delay, slide, edge reveal and reversal on all four positions. Drag rail icons and use its context menu; the rail stays open. Move and resize a window flush with the screen bottom, then reveal Pelicom above it and check its icons receive clicks while covered window controls do not. Hidden rail clicks should reach the window. Disable auto-hide while hidden; the rail returns immediately. Reload and check the checkbox and per-farmer position persist. Right-click Pelicom and confirm only Reset icon order remains. Switch categories; resize, move, minimize, restore and group the window. Reload the save and check its placement/open state.
2. Toggle a gameplay setting, change audio sliders, and select dropdown values. Check the corresponding vanilla menu and persistence after relaunch. Confirm Multiplayer and Screenshot remain fully readable and slider values retain the percent sign, including 55% and 100%.
3. Change UI scale, window mode and zoom. Confirm the window and dropdowns remain within the viewport, and the HUD zoom controls still update the displayed setting.
4. Rebind a key; reject a duplicate; cancel with Escape; reset bindings. Confirm ordinary keyboard input resumes after each action and F8 still works.
5. Take a map screenshot and open its folder. In co-op, check host-only settings, invite dialogs and local co-op startup.
6. Under System → Experimental, enable Extended queue and drag across more than nine ready machines. Confirm every target has a bracket, adjacent colors form a gradual rainbow, and collection continues after release. Ctrl/Shift-select more than nine Overview rows and bulk Collect them. Disable the checkbox during a long queue: existing work and brackets remain, while new additions wait until fewer than nine targets remain. Reload and confirm the checkbox persists. With it off, the tenth target still plays `cancel`.
7. Choose Box select in Right-click drag. Start on empty ground and drag in each direction around ready machines, crops and other interactables. Check the white fill/checkered border at different zoom levels, and that release queues the final rectangle once per target. Grow then shrink a box; targets outside its final bounds should not queue. Try more than nine targets with Extended queue on/off, release over UI, Shift/manual movement/F8 cancellation, single right-clicks and an existing route. Reload and confirm the mode persists; switch back to Per-tile and check the original stroke behavior.
