# Overview menus

Right-click an NPC in Overview for **Talk**, **Gift**, and **Approach**. Gift lists backpack stacks under Loved and Liked, sorted by name, with quality and quantity shown. Stardrop Tea appears under Loved. Neutral, disliked, hated, quest and non-giftable items are excluded. Gift is disabled when no listed stack can currently be given. Daily/weekly limits, birthdays, spouses, divorce, sleeping/invisible NPCs, first-year green rain and NPC item refusals are checked when opening, while the menu is open, and on arrival.

Selecting a gift walks into range and offers one item from that exact stack through the native NPC item-receiving action. NPC movement retains the selected gift callback. Inventory changes, NPC removal, map changes and day changes invalidate pending actions. The selected toolbar slot and stow state are preserved. Native delivery/quest handling and gift reactions still apply. Talk temporarily stows the carried item and invokes the selected NPC's native dialogue/social/shop action, so holding a gift does not give it accidentally. Pets and horses keep their generic interactions.

Ready machines, crab pots and tappers offer **Collect** through the existing output-only collection probe. Collection rechecks readiness and target identity on arrival and calls the machine's native collection action without inserting held input. Other actionable targets retain Interact. Approach, category hiding and Lookup Anything's Show Info remain shared window actions.

Livestock offer **Inspect** and **Pet**. Inspect immediately opens the selected animal's vanilla info screen, including before petting and while sleeping, without changing its petting state. Pet walks into range and pets that exact animal through the native action; it is greyed out when already hand-petted, sleeping, removed, or when a held golden animal cracker would trigger feeding instead. Auto-petted animals can still be hand-petted. Pet eligibility updates while the menu is open and is checked again on arrival. Pets and horses retain their generic interactions; the vanilla livestock info screen accepts farm animals only.

## Selecting and queuing groups

Plain-click selects one row. Ctrl-click toggles individual rows; Shift-click selects a contiguous range in the current grid sort order, and Ctrl+Shift adds a range. Selection and the movement queue share `ClickToMove.MaxQueued` (currently nine). A tenth selection or oversized range plays `cancel` and preserves the previous group. The footer shows the selected count and modifier controls. Rescanning and sorting preserve stable row identities; hidden, removed and stale rows leave the selection, and changing farmer/day clears it.

Right-clicking a selected row preserves the group; right-clicking an unselected row selects it alone. Bulk menus offer queued actions for eligible matching targets: **Pet** pets selected unpetted livestock, **Collect** collects selected ready machines, and Talk/Interact work for their matching targets. Mixed selections may expose both Pet and Collect; each action affects its eligible subset. Immediate Inspect and Gift submenus stay available for single selections. Approach visits selected targets without using tools or interacting; category hiding and Show Info refer to the clicked row. Double-click still approaches one row; Ctrl-click now selects instead of approaching.

Bulk actions resolve and validate their requests again on click, remove duplicates already queued, and append one optimized batch after existing work. If the whole valid batch cannot fit in the remaining queue slots, it plays `cancel` and queues none of it. Unreachable targets are skipped. Pathfinding uses four-way walking distances around obstacles and an exact subset search over target order and walkable interaction sides, minimizing the open tour without returning to the starting tile. Each distance search retains the existing 20,000-tile work bound. Optimization starts at the projected end of existing queued work and applies to the new batch only. Chosen sides are retained when the legs start; moving animals or changed obstacles invalidate the snapshot side and trigger normal live replanning with the selected action intact. Readiness, identity, location/day and normal cancellation checks still apply on arrival.

## Adding actions

`Interactions/OverviewContextMenuRouter.cs` owns ordered `IOverviewContextMenuProvider` implementations. Register a provider there and return `null` for targets it does not handle. Returning an array claims the target; an empty array suppresses the generic Interact fallback. Providers receive the selected entity, location, farmer, live tile lookup and lifetime guard, plus the window's queue callback. This is independent of `WorldContextMenuRouter`, which adapts native question-dialogue choices from world clicks.

Use `OverviewMenuRequest.Action` to resolve the selected action again at click time, validate it and send its `InteractRequest` into the existing movement queue. Supply an availability predicate for changing state. Keep readiness and identity checks in the request's `Valid` and `Perform` callbacks too; menu eligibility is not a substitute for arrival validation. Moving targets need an `ApproachTarget.LiveTiles` callback so chase replans retain the chosen action instead of resolving generic interaction. Prefer the selected entity's native action over a location tile lookup when overlapping targets could select another entity.

`Action` also registers the resolver for bulk menus. `CreateMany` groups top-level queued actions by their text and resolves the eligible rows into a single `EnqueueInteractions` batch. Immediate menu callbacks and submenu leaves do not participate. Use an `InteractRequest.Identity` for moving entities so overlapping targets stay distinct and repeated batches deduplicate.

`ContextMenuItem.CanExecute` provides live enablement alongside static `IsEnabled`. Disabled rows consume clicks. A parent becoming disabled closes its open submenu. The overview guards actions recursively, including submenu leaves, and releases desktop focus when queuing a request.
